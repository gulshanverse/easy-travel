## 8. Production Configuration Verification

`assertProductionConfig` rejects in-memory drivers whenever the environment is
`production`, naming every offender:

- `InMemoryDatabaseDriver` → rejected
- `InMemoryCacheDriver` → rejected
- `InMemoryObjectStorageDriver` → rejected

Each pillar is additionally rejected individually. `development` and `test`
environments continue to permit in-memory drivers. `createProductionConfig()`
selects postgres + redis + s3 and refuses to construct a runtime unless the
structural clients (SQL client, Redis transport, storage signer/transport) are
injected.

## 9. Optional Enhancements Delivered

Implemented as persistence implementations only — no runtime engine modified.

- **EventStore** — append-only, per-stream monotonic sequencing, optimistic
  `expectedSequence` concurrency check, `read(from)` and deterministic `replay`.
- **AuditStore** — append-only trail with actor/owner, action, before/after
  snapshots, queryable per record and per actor.
- **OutboxStore** — transactional outbox with `enqueue`, `pending`, `drain`,
  exponential backoff on failure and terminal `failed` after `maxAttempts` (3).

## 10. Technical Debt

1. `PostgresDatabaseDriver` transactions use a compensating journal rather than
   real `BEGIN/COMMIT`, because the edge runtime reaches Postgres through the
   managed Data API. Isolation is per-statement; conflicting concurrent writers
   rely on optimistic locking.
2. Event, audit and outbox stores persist through `persistence_records` in the
   generic driver path; the dedicated `persistence_events`/`persistence_audit`/
   `persistence_outbox` tables exist and are ready, but binding them requires a
   per-store driver mapping (currently one physical table per store is unused in
   the in-memory path).
3. Repository-level filtering for the Postgres driver pushes only equality
   predicates down; richer specifications are evaluated in memory after fetch.
4. Project-wide Prettier formatting debt remains outside `src/lib/persistence`
   (~8 000 formatting-only findings in older sprints); persistence code is clean.
5. `tests/prompt/runtime.test.ts > hits semantic cache on second identical run`
   is timing-sensitive and has been observed flaking once under full-suite load;
   it passes in isolation and on re-run. Not touched — prompt engine is frozen.

## 11. Known Limitations

- Prisma is not used: it cannot run in the Cloudflare Workers/edge server runtime.
  The Postgres driver targets the managed Data API behind the same repository
  abstraction, so engine contracts are identical either way.
- Redis uses the HTTP/REST protocol; TCP Redis clients are unavailable at the edge.
- Object storage `s3`/`azure`/`gcs` drivers require an injected signer and
  transport; no vendor SDK is bundled.
- Cross-collection (multi-table) atomicity is bounded by the compensating journal.
- RLS scopes rows to `owner_id = auth.uid()`; system-owned rows (`owner_id NULL`)
  are reachable only through backend/admin paths.
